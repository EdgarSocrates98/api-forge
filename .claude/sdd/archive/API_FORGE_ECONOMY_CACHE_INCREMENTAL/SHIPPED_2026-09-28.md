## Summary

API Forge now reuses verified evidence instead of recomputing it. A layered,
advisory cache (`rules/cache_policies.yaml`) enforces L2 graph snapshots keyed
by case content, an L3 impact memo and an L4 capsule *selection* cache whose
entries carry dependency probes — file, line-span and JSON-pointer hashes, the
graph neighborhood of the nodes used, model definitions and test mentions — so
an edit invalidates exactly the capsules it touches and an unrelated edit keeps
them. `context delta` starts PR work from the change set (read-only git or
`--changed`) and lists impacted operations and capsule targets. Capsule output
is byte-identical with and without the cache.

## Lessons Learned

### Process

- Put a precision gate in the eval from day one: it exposed that whole-file dependencies invalidated every capsule on any contract edit.
- In this Windows shell, never pass backslash escapes through heredocs; edit such code with the editor tool.

### Technical

- Cache what is expensive and stable (the selection), recompose what embeds volatile identity (the fingerprint).
- Symbol scans must look for *definitions*, not mentions; mentions of a type in a field declaration are not a new model.
- `openapi.diff` classifies compatibility, not change; delta needs subtree comparison with the `$ref` closure.

### Communication

- State the granularity honestly: delta is file-level, cache is slice/pointer-level.
