## Summary

API Forge moved from feature-driven to evidence-driven. The harness (`apiforge field record|annotate|verify|report|export`) lets the owner run a pre-registered field cycle (30 tasks or 4 weeks, 6 scenarios) on real repositories. It records why the user left the API Forge flow, joins the metrics from existing run artifacts, requires blind verification, and produces a deterministic gap report with Wilson 95% CIs, theme qualification and a verdict on a pre-registered hypothesis (H1: `graph_gap` dominates). In parallel, `workspace graph --infer` adds static cross-repo `calls` and `publishes_to_consumer` edges. These edges are isolated from baseline runs through an audited ledger row and can be proven only by the A/B phase. The next structural SDD is chosen from the field report, not from intuition.

## Lessons Learned

### Process

- Put an adversarial critic in the brainstorm, before DEFINE. It reshaped scope before any design work: 12 scenarios became 6, 15 metrics became 10, and the SDD gained a pre-registered hypothesis and an exit gate. Changing those later would have meant rewriting the design.
- When the owner overrides the recommendation (approach C instead of A), write the guardrail down right away (flag off in baseline, A/B at the end). This keeps the override without losing a valid measurement.
- Grep the existing contracts before writing a DESIGN ADR that depends on a data field. Decision D2 assumed ledger timestamps that do not exist, and it was corrected only at build time.

### Technical

- Derive integrity signals from persisted evidence (the `workspace.infer` ledger row), not from operator flags. Contamination then becomes testable end to end.
- `resilience.http_call` facts have no target path. Cross-repo HTTP inference needed its own extractor, and the stable resilience fact contract was left unchanged.
- `sdd check` hashes text with `text_sha256`. Pytest output captured on Windows mixes CRLF and LF, so normalize evidence to LF before stamping.
- Python `write_text` on Windows writes CRLF. Use `newline="\n"` in scripted edits to this LF repository.

### Communication

- Spec versions pasted from another LLM (Arazzo 1.1, OpenAPI 3.2.1) came with unresolved citation markers. Mark them `unresolved` at intake so they never drive decisions.
- The memory rule "bare `/design`/`/build` = SDD phase" prevented a wrong route to the visual-design artifact flow.

### Tools & Libraries

- `apiforge sdd classify` set the profile (`critical`) from paths and keywords, which removed debate over rigor.
- Wilson from the standard library (no scipy) kept the report deterministic and dependency-free.
- `pytest-xdist` is not installed. The serial full suite takes about 3 minutes, so plan for it.
