## Lessons Learned

### Process

- A shared artifact loader should be introduced as soon as multiple surfaces
  consume the same JSON envelope; otherwise compatibility fixes drift.
- Running the global formatter before the final release gate exposed a large
  baseline issue without requiring semantic changes; the full suite must follow
  any mechanical rewrite.

### Technical

- Capability state is safer as a closed vocabulary than as a boolean because
  static usefulness, missing evidence and intentional refusal are different
  outcomes.
- A read-first integration gateway lets Git, CI/CD, cloud, data and messaging
  be documented now while preventing accidental claims of live mutation.

### Communication

- The requirement was clarified from a guided user experience to agents that
  understand needs and recommend practices/architectures; the final docs now
  make that distinction explicit.
- Naming the production boundary in README and capability docs prevents a
  fixture or parser from being misunderstood as provider support.

### Tools & Libraries

- The `skill-creator` guidance kept the canonical skill concise and routed
  detailed usage to a maintained guide instead of duplicating manuals.
- Ruff format, Ruff lint, mypy and pytest provided independent deterministic
  gates for the broad baseline change.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Provider integrations | Add one read-only provider adapter at a time with credentials, policy, receipt, verifier and holdout evidence. |
| IDE/UI | Select the first concrete protocol/runtime and ship it as a projection over the existing canonical contracts. |
| Security | Install and integrate external scanners behind allowlisted adapters; keep absent tools as explicit unresolved prerequisites. |
| Performance | Add measured baselines and repeat runs before making TPS, latency or cost claims. |
