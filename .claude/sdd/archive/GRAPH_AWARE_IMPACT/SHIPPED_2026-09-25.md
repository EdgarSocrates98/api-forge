## Summary

Graph-Aware Impact adds a versioned, immutable `GraphImpactAssessment/v1` that performs bounded deterministic reverse traversal over explicit local graph evidence. The same assessment governs verification depth, graph-aware candidate selection and explainable runtime briefs while preserving A's risk/complexity authority, B's scorecard evidence, unresolved states, provenance and offline boundaries.

## Lessons Learned

### Process

- Keeping C as a separate SDD cycle preserved A and B as explicit compatibility authorities instead of merging three policy concerns into one unreviewable change.
- Running the full suite against an external temporary directory was necessary because Windows sandbox/worktree tests interpret in-repository pytest artifacts as dirty state.

### Technical

- A single immutable assessment can safely serve gate, selection and projection when traversal bounds, evidence and unresolved semantics are part of its identity.
- Preserving the public `schema` wire field while filtering only the exact Pydantic legacy-shadow warning removed noise without changing contract payloads.

### Communication

- Naming the three consumers—verification gate, candidate selection and explainable brief—made the C scope measurable and prevented independent recalculation.
- Recording B's shadow-evaluation and C's graph evidence as separate extension boundaries kept the offline MVP deterministic.

### Tools & Libraries

- Existing Pydantic versioned contracts and the registry made additive graph contracts discoverable and replay-safe.
- Pytest fixtures, Ruff, mypy, the release gate and SDD/spec checks supplied independent local evidence before archival.
