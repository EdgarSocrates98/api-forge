## Summary

Intelligent Capability Routing shipped as an offline-first, deterministic runtime extension. It separates safety and evidence eligibility from efficiency/quality ranking, records explicit unknown signals and fallback order, persists an auditable routing trace, and prevents scorecard promotion unless evaluation evidence passes the existing quality gate.

## Lessons Learned

### Process

- Confirming the priority order early — efficiency first, security as a hard guardrail, quality after — kept the first slice bounded and explainable.
- Running the release catalog gate before archival exposed missing contract documentation while the change was still easy to correct.

### Technical

- Separating eligibility from ranking makes the security invariant locally testable and prevents historical scorecards from bypassing policy.
- Explicit `unknown` and `unresolved` signals are safer than numeric defaults because they preserve evidence limitations in both ranking and replay.

### Communication

- Recording that `prompt_evo_nova_avaliacao.md` must not be committed preserved the source prompt as user-owned input.
- Writing unresolved benchmark questions into the design made the shipped boundary clear: the MVP routes deterministically but does not claim an efficiency gain.

### Tools & Libraries

- Pydantic versioned contracts made additive scorecard evolution and actionable validation errors straightforward.
- Pytest, Ruff, mypy and the repository release checker provided independent verification layers for behavior, style, types and catalog completeness.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Benchmarking | Establish a local corpus, baseline duration/cost observations and a measurable improvement target before adding numeric weights. |
| Ranking policy | Add weighted or adaptive ranking only after attributable evidence and rollback criteria are available. |
| External ground truth | Introduce provider observations only through the existing read-only adapter, receipt and freshness boundaries. |
