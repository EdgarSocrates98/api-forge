## Lessons Learned

### Process

Quebrar o programa em uma Wave 0 contratual tornou possível verificar o gate
sem misturar providers, CLI/TUI e governança externa. O próximo ciclo deve
manter a mesma regra: abrir uma onda somente após o exit gate anterior.

- Registrar o manifest antes do build evita que arquivos auxiliares de release
  fiquem fora do controle de escopo.
- Rodar o release gate antes do arquivamento encontrou documentação ausente de
  contratos registrados, corrigida antes do ship.

### Technical

- O fallback estático pode ser representado por uma referência determinística
  `{run_id}:static-routing`, sem inventar uma infraestrutura de rollback.
- Separar `EvidenceCoverage` de `PromotionGate` preserva a diferença entre
  evidência presente e autoridade para executar.

### Communication

- Declarar desde o DESIGN que `shadow`, `replay` e `external-read` não são
  autoridade ativa evitou ambiguidade na integração do supervisor.
- Marcar acceptance tests de ondas futuras como seladas torna o status do ship
  honesto sem transformar lacunas planejadas em falhas silenciosas.

### Tools & Libraries

- Pydantic v2 com `VersionedContract` forneceu validação fechada, imutabilidade
  e invariantes de transição com pouca superfície adicional.
- Ruff, mypy, pytest, release gate e AgentSpec spec-linter formaram um conjunto
  independente de validações para código, contratos e processo SDD.
