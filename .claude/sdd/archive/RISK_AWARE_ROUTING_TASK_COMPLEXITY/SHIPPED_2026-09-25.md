## Summary

The MVP adds a versioned, local and deterministic `RiskComplexityAssessment/v1` that combines explicit task risk and complexity inputs before routing. The canonical assessment is carried through `RoutingDecision/v1`, `RoutingPlan/v1`, runtime persistence and read-only runtime/CLI/TUI/governance projections, preserving evidence, unresolved diagnostics, refusal details and replay identity. Scorecard-adaptive routing (B) and graph-aware impact analysis (C) remain explicit future extensions and are not activated by this shipment.

## Lessons Learned

### Process

- Keep the policy contract, fixture matrix and projection parity requirements in the DEFINE/DESIGN artifacts before implementation; this prevented separate runtime and surface interpretations.
- Record environment-sensitive test failures as deviations instead of treating a later green run as if the earlier evidence did not exist.

### Technical

- A pure classifier backed by versioned YAML makes replay identity explicit and allows policy changes to be tested as data mutations.
- Unknown routing signals can remain visible in `unresolved` without becoming an invented hard refusal; only assessment blockers and missing required roles gate the plan.
- Additive routing fields and required-role candidates preserve legacy specialist selection while allowing complexity to change review composition.

### Communication

- Confirming “A now, B/C later” early kept the MVP bounded and made the extension seams deliberate rather than accidental.
- Naming the three consumer surfaces—runtime, CLI/TUI and governance—early clarified that all projections must read the canonical persisted result.

### Tools & Libraries

- Existing pytest fixtures and evaluation categories provided the local replay, holdout, mutation and adversarial evidence needed for an offline-first ship.
- Ruff, mypy and the repository SDD/spec checks provided independent static and workflow gates beyond the focused tests.
